# MCP 원자 도구 계약 (요약)

스킬(오케스트레이터 — 진입점 `upplz-init` 포함)이 호출하는 upplz MCP 도구(22개). 상세 파라미터는 도구 자체 설명 참조. 사전조건 게이트는 도구가 최종 방어한다.

**격리 단위는 프로젝트다.** API 키 하나가 프로젝트 하나를 가리키고, 식별자·인증서 저장소·프로젝트 비밀번호·Bundle ID·빌드는 모두 그 프로젝트 소유다.

**역할은 둘이다** — `owner`(공유 자산을 만들고 바꾼다) / `collaborator`(협업자 — 빌드·업로드·테스터·스토어 메타데이터 전부). 게이트는 하나뿐이다:

- **owner 전용 3종**(`requireOwner` → `OWNER_ONLY`): `register_ios_credentials`·`register_android_credentials`·`setup_match_repo`. 3종 모두 **공유 자산을 만들거나 바꾸는** 도구다. `setup_android_keystore` 는 **조건부** — 저장소 URL·프로젝트 비밀번호가 저장된 프로젝트에서 파라미터 없이 부르면 협업자도 통과하고, 아니면 `OWNER_ONLY` 다(D3).
- owner 전용 3종 + 조건부 1종을 뺀 나머지 18개는 활성 멤버 누구나 호출한다(`register_bundle_id`·`add_provisioning_profile`·`start_build`·`sign_android_bundle`·`upload_to_store`·`add_testers`·메타데이터 도구 포함).

**자격이 사는 곳과 전달되는 것**:

- 파일 자산은 전부 **인증서 저장소**(owner 소유 private GitHub, 프로젝트 시크릿 `ios/match-repo-url`)에 있다 — match 인증서·프로파일, `android/<packageName>.keystore`, `upplz/ios/AuthKey.p8.enc`(Apple 팀 키), `upplz/android/service-account.json.enc`(Play Service Account). `.enc` 는 `openssl enc -aes-256-cbc -pbkdf2 -iter 200000` 으로 암호화돼 있다.
- **응답에 실리는 비밀값은 `env.MATCH_PASSWORD`(프로젝트 비밀번호) 하나**다. 스크립트를 돌려주는 모든 도구가 이 값을 싣고 `audit_logs` 에 `matchPasswordDelivered` 를 남긴다. 응답에 `requiredEnv` 가 있으면 언제나 `["MATCH_PASSWORD"]` 다. Key ID·Issuer ID·Team ID 는 비밀이 아니라 스크립트 본문에 리터럴로 들어간다.
- 프로젝트 비밀번호가 저장돼 있지 않으면 스크립트 도구는 전부 `PRECONDITION_FAILED` 다(저장 경로는 `register_ios_credentials`·`register_android_credentials`·`setup_android_keystore`(Android 전용 첫 셋업) 의 `matchPassword` — 전부 owner 전용. `setup_match_repo` 는 비밀번호를 받지 않는다). **이미 저장돼 있으면 어느 도구도 다른 값을 받지 않는다**(`PRECONDITION_FAILED` — 저장값이 이미 저장소의 파일을 잠갔으므로 바꾸면 전부 풀리지 않는다). `get_setup_status` 의 `apple.matchPasswordStored: true` 면 넘기지 않는다.
- **스크립트 실행 규칙**: `env.MATCH_PASSWORD` 를 export → 스크립트를 **파일로 저장해 통째로** 실행(`bash <파일>` — 인라인 `bash -c '<본문>'` 은 Claude Code 안전 검사가 `rm -rf "$WORKDIR"` 때문에 차단한다) → 끝나면 unset·파일 삭제. 프롤로그가 `[preflight]`(openssl·비밀번호·저장소 접근) → 임시 디렉토리 + `trap` → shallow clone(`[fetch]`) → 필요한 파일만 복호화(`[decrypt]`, 0600) 순으로 돈다. `[fetch] … 가 없습니다` 는 owner 가 지목된 등록 도구를 실행해야 한다는 뜻이다. `[decrypt]` 는 먼저 응답 `env.MATCH_PASSWORD` 를 그대로 export 했는지 확인하고, 맞으면 owner 가 그 파일의 등록 도구(`.p8` → `register_ios_credentials`, Play SA → `register_android_credentials`)를 다시 실행해야 한다는 뜻이다(같은 저장소를 다른 upplz 프로젝트도 쓰면 재실행 대신 대시보드 '다른 프로젝트에서 복사' 로 비밀번호를 맞춘다 — 응답 `troubleshooting.passwordMismatch` 가 파일 종류별 공용 문장이다).

> **인증서 저장소는 플랫폼 공통이다.** 프로젝트 시크릿 키 이름이 `ios/match-repo-url` 이지만 **Android 도 같은 값을 읽는다** — iOS 의 match 저장소와 Android 의 keystore·SA 저장소는 **같은 private GitHub 저장소 하나**다(`ios/` 접두사는 iOS 가 먼저 생겼다는 역사적 흔적일 뿐이며, 키 이름은 마이그레이션 비용 때문에 바꾸지 않는다). iOS 를 이미 설정한 프로젝트라면 Android 는 저장소 URL 을 다시 넣지 않아도 되고, Android 전용 프로젝트는 `register_android_credentials`/`setup_android_keystore` 의 `matchRepoUrl` 파라미터로 등록한다.

## 온보딩/셋업
- `get_setup_status` — **iOS·Android 첫 배포 셋업 상태 종합 판정(read-only)**. 온보딩 시작·재개 시 **첫 도구 호출**로 쓰고, 셋업 단계 하나를 끝낼 때마다 다시 호출해 `nextStep`으로 분기한다(first-time-setup.md "셋업 완료 판정"). **서버는 Apple·Google 을 조회하지 않는다 — DB 기록(시크릿 존재·audit·빌드)만 본다.** 파라미터: `platform?`(`ios`(기본)|`android` — 최상위 `nextStep`·`nextStepHint`·`setupComplete` 를 어느 블록 것으로 채울지만 고른다. **서버는 프로젝트가 어느 플랫폼인지 추정하지 않는다 — 호출자가 고른다**), `bundleId?`(`register_bundle_id`로 이미 저장된 ID와 다른 ID를 확인할 때만 — 저장 전에는 넘기지 않는다), `packageName?`(Android 패키지명 — **판정에는 참여하지 않고** `nextStepHint` 의 요청문(`setup_android_keystore({ packageName: "com.example.app" })`)에 실제 값을 찍는 데만 쓴다). 응답: `platform` / `team.role`(`owner`|`collaborator`) / `apple{ credentials(Key ID·Issuer ID·Team ID 3종 존재), matchRepoUrl, matchInitialized(setup_match_repo 발급 기록 **또는** 상속 기록 — 약한 근거), matchInitInherited(상속 마커 `ios_match_init_inherited` 존재), matchPasswordStored(값은 반환하지 않는다), profileIssued(현재 Bundle ID 의 프로파일 발급 기록) }` / `bundleId`(string|null) / `nextStep` / `nextStepHint`(한국어 한 문장, 사용자에게 그대로 안내) / `setupComplete` / **`ios{ nextStep, nextStepHint, setupComplete }`·`android{ certRepoUrl, keystoreScriptIssued, buildSucceeded, keystorePrepared, serviceAccountStored, nextStep, nextStepHint, setupComplete, nextVersionCode }` — 두 블록은 항상 함께 온다**. `android.nextVersionCode` 는 `report_build_result` 로 기록된 Android `versionCode` 최댓값+1(기록 없음 = 1)이며 **힌트**다 — 빌드는 에이전트가 하고 Play 는 더 큰 값만 받는다. iOS nextStep 5종(`register_ios_credentials`|`register_bundle_id`|`setup_match_repo`|`add_provisioning_profile`|`start_build`), `apple.matchInitInherited`(다른 프로젝트에서 물려받은 초기화 기록)·`apple.profileIssued`(현재 Bundle ID 의 프로파일 발급 기록). Android `nextStep`: `setup_android_keystore`(저장소 URL 부재 또는 keystore 미준비 — `android.certRepoUrl` 로 구분)|`register_android_credentials`|`sign_android_bundle`(셋업 완료 — 빌드는 에이전트가 직접 하고 upplz 는 서명만). 역할은 판정을 바꾸지 않고 `nextStepHint` 문구만 바꾼다(owner 전용 단계면 "owner 가 해야 한다" 요청형, 저장소를 clone 하는 단계면 비-owner 에게 GitHub collaborator 안내가 붙는다). **확인하지 않는 것(힌트로만)**: ASC 앱 레코드·프로비저닝 프로파일의 Apple 쪽 실존(발급 기록은 본다)·저장소 안 파일 실존·협업자의 저장소 권한·Play Console 앱 생성. 에러: `{ error: "Unauthorized" }` / `SETUP_STATUS_FAILED`(서버 일시 장애, 재시도).
- `analyze_repository` — 저장소 구조·projectType 분석.
- `register_ios_credentials` — **owner 전용**(`OWNER_ONLY`). Apple 팀 키 등록·교체. 파라미터: `authKeyPath`(**.p8 파일의 절대 경로** — 본문을 읽어 넘기지 않는다. 영문·숫자·공백·`._@/-` 만) / `keyId` / `issuerId` / `teamId` / `matchRepoUrl?`(프로젝트에 아직 없을 때만 — 미입력 시 저장값, 둘 다 없으면 `PRECONDITION_FAILED`. 넘기면 덮어쓴다) / `matchPassword?`(8자 이상 — 프로젝트에 비밀번호가 없으면 **필수**, 있으면 넘기지 않는다 — 다른 값은 거부). 서버는 식별자 3종(+넘긴 URL·새로 정한 비밀번호)을 저장하고, 응답 `script` 가 사용자 맥에서 `.p8` 를 확인(`openssl pkey`)·암호화해 `upplz/ios/AuthKey.p8.enc` 로 push 한다(같은 파일이면 `[done] 변경 없음`). 응답: `stored`(저장된 키 목록) / `replaced`(**저장돼 있던 Key ID 가 이번 값과 다를 때만 true** — 같은 키 재등록·기존 프로젝트 이관은 false) / `previousKeyId?`(replaced 일 때 — Revoke 대상) / `certRepoPath` / `script` / `env.MATCH_PASSWORD` / `execution` / `troubleshooting{ repoAccessDenied, pushRejected, notAPrivateKey, passwordMismatch }` / `nextStep`. 형식 오류는 `INVALID_INPUT` + `errors`(필드별 안내)이며 **입력값은 응답·로그 어디에도 되돌아오지 않는다**.
- `register_android_credentials` — **owner 전용**(`OWNER_ONLY`). Play Service Account 등록·교체. 파라미터: `serviceAccountPath`(**키 파일의 절대 경로** — 본문을 읽어 넘기지 않는다) / `clientEmail`(`jq -r .client_email <파일>` 또는 `node -e 'console.log(require(process.argv[1]).client_email)' <파일>` 로 뽑은 공개 식별자) / `matchRepoUrl?`(미입력 시 프로젝트의 저장소 URL, 둘 다 없으면 `PRECONDITION_FAILED`) / `matchPassword?`(프로젝트에 없으면 **필수**, 있으면 넘기지 않는다 — 다른 값은 거부). 서버는 `android/service-account-email` 에 `clientEmail` 을 저장하고(이 키의 존재가 "SA 등록됨"), 응답 `script` 가 `node` 로 파일을 확인(`type=service_account`·`client_email` 일치·`private_key`)한 뒤 암호화해 `upplz/android/service-account.json.enc` 로 push 한다. 교체면 옛 `private_key_id` 를 출력한다(Google Cloud 에서 그 키 삭제). 응답: `replaced` / `clientEmail` / `certRepoPath` / `script` / `env.MATCH_PASSWORD` / `nextStep`.
- `register_bundle_id` — 활성 멤버 누구나. 로컬 Bundle ID 등록 스크립트 반환(fastlane 의 Spaceship ConnectAPI `BundleId.find`→`create` lane — `fastlane produce` 는 Apple ID 로그인 전용이라 API 키를 받지 않는다, 2026-10-19 실측)(Developer Portal Bundle ID 등록 — 스크립트가 저장소에서 `.p8` 를 풀어 쓴다. 이미 있으면 `[bundle-id] 이미 등록된 Bundle ID` 로 exit 0). **ASC 앱 레코드는 만들지 않는다** — App Store Connect API 가 앱 생성을 지원하지 않아 사용자가 ASC 웹(My Apps → + → New App)에서 직접 만든다(App Manager 이상). 사전 조건: `register_ios_credentials` 완료 + 프로젝트 비밀번호.
- `setup_match_repo` — **owner 전용**(`OWNER_ONLY` — 인증서 발급·`forceNuke` 가 프로젝트 전체의 코드서명 자산을 바꾼다). match 저장소 초기화 + 공용 Distribution 인증서 + 첫 프로파일 로컬 스크립트(파라미터: `matchRepoUrl?`, `forceNuke?`). **비밀번호 파라미터가 없다** — `register_ios_credentials` 가 저장한 값을 `env.MATCH_PASSWORD` 로 싣는다. 사전 조건: `register_ios_credentials`(식별자·프로젝트 비밀번호) + `register_bundle_id`(`ios/bundle-id`). 응답 `matchPassword`는 정책 안내 객체(`policy`/`firstTime`/`existing`)이며 **값은 포함되지 않는다**(값은 `env.MATCH_PASSWORD`). 스크립트는 fastlane 실행 전에 **fastlane 설치·저장소 접근**을 점검하고 clone 뒤 **match 초기화 여부**(match 가 쓰는 브랜치(`MATCH_GIT_BRANCH`, 기본 `master`) 의 `match_version.txt` — 기본 브랜치의 트리가 아니다. GitHub 새 저장소는 기본 브랜치가 `main` 이라 upplz 파일은 `main` 에, match 는 `master` 에 쓴다)로 새 저장소·기존 저장소를 알려 주며, 실패 원인은 응답 `troubleshooting{ fastlaneMissing, repoAccessDenied, passwordMismatch, certLimit }`(`src/lib/ios-match-script.ts` `buildMatchTroubleshooting()`)로 안내한다. match 미초기화 저장소는 최초 초기화로 간주해 계속 진행한다(저장소에는 `register_ios_credentials` 가 넣은 `upplz/ios/AuthKey.p8.enc` 가 이미 있으므로 "비어 있는가" 로는 판정하지 않는다).
- `add_provisioning_profile` — `nextStep: add_provisioning_profile` 이 가리키는 정식 단계(D5)이기도 하다 — 활성 멤버 누구나. 다른 Bundle ID(익스텐션·두 번째 앱)의 프로비저닝 프로파일을 저장소에 추가하는 로컬 스크립트(`bundleId?` — 미지정 시 `ios/bundle-id`). 인증서는 재사용한다. match 는 멱등이라 같은 ID 로 다시 실행해도 안전하다. **match 미초기화 저장소(match 브랜치 — 기본 `master` — 에 `match_version.txt` 없음)면 `[match]` 오류(exit 1)로 중단**한다(owner 가 `setup_match_repo` 를 아직 안 했다는 뜻 — 팀 멤버가 read-write match 로 새 Distribution 인증서를 만들어 버리는 것을 방지). ASC 앱 레코드는 필요 없다. 실패 원인은 같은 `troubleshooting` 객체로 안내한다.
- `setup_project` — 로컬 스캐폴드(Capacitor 등) + 로컬 커밋. `platform`(`ios`(기본)|`android`) 파라미터로 대상 선택. `bundleId`는 항상 필수(zod 레벨). platform=ios(기본)는 `iconUrl` 파라미터로 초기 아이콘 지정 가능. platform=android 는 **스캐폴드하지 않는다** — `ANDROID_SCAFFOLD_REMOVED` 안내만 돌려준다. Android 프로젝트는 에이전트가 저장소에 맞는 방법으로 직접 준비한다(Capacitor 면 `npm i @capacitor/android@<core 와 같은 버전>` → `npx cap add android` → `npx cap sync android`).
- `setup_android_keystore` — 조건부(owner 는 항상, 협업자는 저장소 URL·프로젝트 비밀번호가 저장된 프로젝트에서 `packageName` 만 넘길 때 — 아니면 `OWNER_ONLY`. keystore 는 인증서 저장소에 사는 프로젝트 공유 자산이지만 스크립트가 기존 파일을 덮어쓰지 않으므로 새 앱의 첫 keystore 는 협업자가 만들어도 Play 업로드 키와 어긋나지 않는다). Android 서명용 keystore 를 **인증서 저장소**에 준비하는 로컬 스크립트 반환(서버는 keystore 파일을 받지도 보관하지도 않는다). 파라미터: `packageName` 필수, `matchRepoUrl?`(미입력 시 프로젝트의 저장소 URL, 없으면 `PRECONDITION_FAILED`), `matchPassword?`(8자 이상 — 프로젝트 비밀번호가 아직 없을 때만, 곧 **Android 전용 첫 셋업**. keystore 비밀번호도 같은 값이다. 없이 부르면 `PRECONDITION_FAILED`, 저장값과 다르면 거부). URL·비밀번호는 모든 검증을 통과한 뒤에만 저장된다 — 이 도구 하나로 Android 전용 프로젝트가 Play Service Account 없이 첫 AAB 까지 간다. 스크립트는 **3분기** — ① 저장소에 `android/<packageName>.keystore` 가 있으면 프로젝트 비밀번호로 열어 보고 재사용(열리지 않으면 `[error]` 와 함께 `keytool -storepasswd` 명령을 출력하고 push 없이 exit 1) ② 이 머신에 옛 keystore 가 있으면 저장소로 **이관**해 push ③ 둘 다 없으면 **호스트 JDK 의 keytool** 로 생성해 push(`keytool -genkeypair -storetype PKCS12 -alias upplz -keyalg RSA -keysize 2048 -storepass:env MATCH_PASSWORD`). 생성·검증 모두 호스트 JDK 다(Docker 없음) — preflight 가 `keytool -help` 로 실행 가능 여부를 본다(맥의 `/usr/bin/keytool` 은 JDK 가 없어도 있는 자리표시자). 비밀번호가 다른 옛 keystore 의 안내 명령은 `keytool -storepasswd -keystore "<경로>/<packageName>.keystore" -storepass:env OLD -new:env MATCH_PASSWORD` 한 줄이다(`OLD`·`MATCH_PASSWORD` 를 export 한 뒤). **어느 경우에도 저장소의 기존 파일을 덮어쓰지 않는다** — Play 앱 서명을 쓰는 앱에서 이 keystore 는 **업로드 키**라 Play Console 의 업로드 키 재설정으로 **교체할 수 있지만** 그동안 업로드가 막히고, **Play 앱 서명을 쓰지 않는 옛 앱**이라면 곧 앱 서명 키라 **교체 불가**다. 응답: `certRepoUrl` / `keystorePath`(저장소 내 상대 경로) / `script` / `env.MATCH_PASSWORD` / `serviceAccountStored` / `nextStep`(SA 미등록이면 `register_android_credentials` 안내) / `troubleshooting{ repoAccessDenied, pushRejected, keystoreDiverged, passwordMismatch }`.

## 빌드/업로드
- `start_build` — 활성 멤버 누구나. **iOS 빌드 도구다** — `platform: "android"` 를 넘기면 빌드하지 않고 `ANDROID_USE_SIGN_TOOL` 안내 오류만 돌려준다(Android 는 에이전트가 직접 빌드하고 `sign_android_bundle` 로 서명한다). 프로젝트 비밀번호가 없으면 `PRECONDITION_FAILED` — "owner 가 `register_ios_credentials` 의 matchPassword 로 저장해야 합니다"(식별자·저장소 URL·match 초기화가 전부 그 도구 선행이라 하나만 가리킨다). preflightScript·buildScript + `env.MATCH_PASSWORD` 반환, `.upplz/App.ipa` 생성. **응답에 Apple API 키(.p8)가 들어 있지 않다** — buildScript 의 match 는 `--readonly` 라 저장소의 인증서·프로파일만 받는다. 서버는 프로파일 존재를 확인하지 않는다(없으면 match 가 실패로 드러낸다 → `add_provisioning_profile`). 게이트: `PRECONDITION_FAILED`(식별자·저장소 URL·비밀번호) / `BUNDLE_ID_REQUIRED` / `MARKETING_VERSION_REQUIRED` / `BUILD_IN_PROGRESS`. repoUrl 필수. projectType 미지정 시 직전 빌드 값→web-capacitor 기본(native 첫 빌드는 반드시 명시, 모호 시 scheme/xcodeProjectPath, 아카이브 구성은 `configuration`(기본 Release — 서명 패치와 xcodebuild 가 같은 구성을 쓴다)).
- `sign_android_bundle` — 활성 멤버 누구나. 서명 없는 AAB(기본 android/app/build/outputs/bundle/release/app-release.aab)를 인증서 저장소의 keystore 로 서명해 .upplz/app-release.aab 를 만든다. 반환: buildId·preflightScript(jarsigner·zip·저장소 접근·비밀번호·AAB)·signScript·env.MATCH_PASSWORD. 저장소 URL·비밀번호 부재는 PRECONDITION_FAILED(setup_android_keystore 안내). 같은 repoUrl 에 보고되지 않은 발급 행이 있으면 `BUILD_IN_PROGRESS`(`existingBuildId`) — start_build 와 같은 가드이며 report_build_result 로 보고한 뒤 다시 부른다. 빌드는 하지 않는다 — start_build 의 platform=android 는 ANDROID_USE_SIGN_TOOL 로 이 도구를 가리킨다. 파라미터: `packageName` 필수, `repoUrl` 필수(어느 호스트든 HTTPS — 기록 키이며 스크립트에 들어가지 않는다), `aabPath?`(프로젝트 루트 기준), `commitSha?`. 서명은 저장소의 `android/<packageName>.keystore`(alias `upplz`)로 **호스트 JDK 의 jarsigner** 가 한다 — signScript 는 저장소 shallow clone → 기존 서명(`META-INF/*.SF|RSA|DSA|EC`) 제거 → `jarsigner -storepass:env MATCH_PASSWORD` → `jarsigner -verify` 로 검증 → `trap` 으로 임시 디렉토리 삭제. keystore 비밀번호 = 프로젝트 비밀번호다. 호출 시 `builds` 행(status=issued)을 만들고 audit `android_sign_issued`(matchPasswordDelivered)를 남긴다. 응답 `execution` 이 다음 순서를 말한다: preflightScript → `env.MATCH_PASSWORD` export → signScript → `report_build_result({ buildId, status: "completed", versionCode, marketingVersion })` → `upload_to_store({ platform: "android", buildId })`. `troubleshooting{ repoAccessDenied, keystoreMissing, jdkMissing, signFailed }` — `[fetch] … keystore 가 없습니다` 는 `setup_android_keystore` 실행, `[sign] 서명 실패` 는 env 값 확인 뒤에도 실패하면 keystore 가 다른 비밀번호로 만들어진 것(`setup_android_keystore` 가 `keytool -storepasswd` 절차를 안내). 협업자 세션이면 `notes` 에 저장소 collaborator 권한 안내가 붙는다. 빌드 힌트(응답 `notes`): release 빌드에 signingConfig 를 넣지 않는다, versionCode 는 `get_setup_status(android).android.nextVersionCode` 를 참고해 빌드 때 넣고 빌드한 값을 그대로 `report_build_result` 에 넘긴다.
- `get_build_status` — 빌드 상태 조회.
- `upload_to_store` — 활성 멤버 누구나. `platform`(`ios`(기본)|`android`) 파라미터. 응답 `env` 는 두 플랫폼 모두 `MATCH_PASSWORD` 하나다. **iOS**: 로컬 pilot 업로드 스크립트(프롤로그가 저장소에서 `.p8` 를 풀어 `api_key.json` 을 만든다). 사전 조건: `register_ios_credentials`(식별자·저장소·비밀번호). 실패 해석은 응답 `appleErrorGuidance`(앱 레코드 없음 등)·`troubleshooting`. VERSION_ALREADY_USED 시 marketingVersion 상향 후 재빌드. **Android**: `uploadScript` 가 **호스트 Node 로 Google Play Developer API** 를 직접 호출한다(Docker·fastlane 없음). 스크립트가 `$HOME/.upplz/play-api` 에 `@googleapis/androidpublisher`·`google-auth-library` 를 1회 `npm install` 하고(고객 저장소에는 설치하지 않는다), 프롤로그가 저장소에서 SA JSON 을 임시 파일(0600)로 풀어 `GOOGLE_APPLICATION_CREDENTIALS` 로 node 에 **경로만** 넘긴 뒤 `trap` 으로 지운다. AAB(`sign_android_bundle` 결과)만 올리고 track 릴리스를 `completed` 로 만든다(메타데이터는 `apply_android_metadata`). `buildId` 는 `sign_android_bundle` 이 돌려준 값이다. SA 미등록(`android/service-account-email` 없음)이면 `PRECONDITION_FAILED`("owner가 `register_android_credentials`로 등록해야 합니다"). buildId가 android 빌드가 아니면 PLATFORM_MISMATCH. 빌드 metadata에 packageName이 없고 파라미터도 없으면 PACKAGE_NAME_REQUIRED. `aabPath`(기본 `./.upplz/app-release.aab`)·`track`(internal(기본)/alpha/beta/production) 선택 파라미터. 응답의 `playErrorGuidance`(PLAY_APP_NOT_FOUND/SA_PERMISSION_DENIED/PACKAGE_NAME_MISMATCH/VERSION_CODE_ALREADY_USED/SA_NOT_IN_CERT_REPO)는 스크립트 실행 결과 해석용 가이드 텍스트다 — **PLAY_APP_NOT_FOUND**: Play 정책상 최초 1회는 Play Console 웹에서 AAB를 수동 업로드해 앱을 생성해야 이후 이 도구가 동작한다. Node.js 가 필요하다(`node -v`).
- `report_build_result` — 빌드/업로드 결과 DB 기록 + 쇼케이스. 파라미터: `buildId`(iOS 는 `start_build`, Android 는 `sign_android_bundle` 이 돌려준 값) / `status` / `versionCode?`(**Android 전용** — 빌드한 AAB 의 versionCode 그대로) / `marketingVersion?`(빌드한 versionName — `x.y.z`). Android 는 둘을 함께 넘긴다 — 빌드 metadata 에 기록되어 `get_setup_status({ platform: "android" }).android.nextVersionCode`(기록된 최댓값+1, 없으면 1)의 근거가 된다. 플랫폼은 빌드가 기록된 `platform`(iOS 는 `start_build`, Android 는 `sign_android_bundle` 에서 확정)을 항상 따른다 — `showcase.platform`은 하위호환용 파라미터일 뿐 판정에 쓰이지 않는다(아이콘이 있을 때만 수집, 대표 스크린샷은 선택). **iOS이고 status가 failed가 아니면 스토어에 공개된 앱일 때 서버가 iTunes Lookup으로 appName/storeUrl/iconUrl/screenshotUrl을 자동 보강**한다(에이전트 제공 값이 우선이며, 빈 필드만 채운다). android는 미지원(직접 제공 필요).

## 메타데이터/에셋
- `pull_ios_metadata` / `apply_ios_metadata` — 활성 멤버 누구나. 스토어 메타데이터 pull/apply(로컬 fastlane deliver). scope=listing|screenshots|all. Key ID·Issuer ID·Team ID 는 등록값을 서버가 스크립트에 넣는다(파라미터로 받지 않는다 — 저장소의 `.p8` 와 다른 Key ID 는 401 이 날 뿐이다). `.p8` 는 프롤로그가 저장소에서 풀어 쓴다. 응답 `env` 는 `MATCH_PASSWORD` 하나. 응답의 `securityNote`·`troubleshooting.keyFileNotFound` 문구를 **그대로 전달**한다. 메타데이터 수정은 팀 키의 ASC 역할이 **App Manager 이상**이어야 한다(Developer 로는 403).
- `pull_android_metadata` / `apply_android_metadata` — 활성 멤버 누구나. Android 스토어 리스팅(제목/설명/릴리스노트/아이콘/스크린샷/피처 그래픽) pull/apply — 응답 `command` 하나가 **호스트 Node 로 Google Play Developer API** 를 호출하는 스크립트다(Docker·fastlane 없음. 패키지는 `$HOME/.upplz/play-api` 에 1회 설치). AAB 바이너리는 다루지 않는다. `packageName` 필수, `metadataPath`(기본 `android/fastlane/metadata/android`) 선택 — 디렉토리 규약(`<locale>/{title,short_description,full_description,video}.txt` + `changelogs/default.txt` + `images/…`)은 그대로다. `apply_android_metadata`의 `scope`(listing|changelog|images|all, 기본 all)·`track`(기본 internal)으로 범위 선택. 응답 `prerequisites`: SA 등록, Node.js(`node -v`), (apply 만) 메타데이터 디렉토리 존재. **Play Service Account 는 프롤로그가 인증서 저장소에서 풀어 쓴다** — `env.MATCH_PASSWORD` 를 export 한 뒤 응답의 `command` 를 **통째로** 실행한다(SA 경로는 `GOOGLE_APPLICATION_CREDENTIALS` 로 node 에 넘기고 `trap` 으로 지운다). `pull` 은 텍스트와 이미지를 한 스크립트가 받고 **릴리스 노트는 받지 않는다**(트랙별 값 — `changelogs/default.txt` 는 직접 작성). 미등록이면 `PRECONDITION_FAILED`("owner가 `register_android_credentials`로 등록해야 합니다"). 최초 AAB가 아직 수동 업로드되지 않은 앱은 `pull`/`apply` 모두 실패한다(troubleshooting 참고).
- `generate_ios_screenshots` — 웹앱(web-capacitor) 스크린샷 생성(Playwright) + frameit(프레임·제목).
- `generate_native_screenshots` — 네이티브 앱(native-ios/flutter/react-native) 스크린샷 생성(xcrun simctl 시뮬레이터, 사용자가 화면 이동 후 Enter로 캡처).
- `generate_app_icon` — 1024 마스터 아이콘 생성 로컬 스크립트(파생 사이즈는 Xcode가 빌드 시 자동 생성). `iconSource`는 이미지(URL/PNG) 또는 **SVG**(rsvg-convert 우선→magick 래스터화, ImageMagick은 항상 필요) — 소스 제공 또는 Claude가 설계한 SVG 생성 택일. optional `appiconsetPath` — 자동 감지(`find .`)가 실패할 때 AppIcon.appiconset 경로를 직접 지정. 크레덴셜 무관, 변경 후 재빌드 필요.

## 테스터
- `add_testers` — 활성 멤버 누구나(iOS 전용 — Android 에는 TestFlight 테스터 개념이 없다). 로컬 테스터 추가 스크립트(임시 Fastfile lane 의 Spaceship ConnectAPI — 이 앱의 그룹을 조회하고 없으면 내부 그룹·모든 빌드 접근으로 만든 뒤 `POST v1/betaTesters` 로 등록. `fastlane pilot add` 는 그룹을 이름만으로 찾아 다른 앱의 동명 그룹에 붙고 API 키로는 배정이 되지 않는다, 2026-10-19 실측)(프롤로그가 저장소에서 `.p8` 를 풀어 쓴다) + `env.MATCH_PASSWORD`. 이미 그룹에 있는 이메일은 `[testers] 이미 등록됨` 으로 건너뛴다(멱등). 앱 레코드가 없으면 `[testers] … 앱이 없습니다` 로 멈춘다(`troubleshooting.appNotFound`), 팀 사용자가 아닌 이메일은 `POST v1/betaTesters` 가 거부한다(`troubleshooting.notTeamMember`). 사전 조건: `report_build_result(status=uploaded)` 로 보고된 빌드. 테스터 관리는 팀 키의 ASC 역할이 **App Manager 이상**이어야 한다(Developer 로는 403). 스크립트가 만드는 그룹은 hasAccessToAllBuilds=true 라 기존 테스터에게 새 빌드가 자동 노출된다(이미 있던 그룹의 설정은 바꾸지 않는다).
